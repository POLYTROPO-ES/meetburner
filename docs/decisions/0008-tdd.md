# 0008. Test-driven development (red/green/refactor)

- Status: accepted
- Date: 2026-10-22

## Decision

All behaviour changes follow TDD:

1. **Red**: write or extend a test that describes the behaviour. Run it and confirm it fails for the expected reason.
2. **Green**: write the minimal code that makes it pass.
3. **Refactor**: clean up with the tests green.

Scope and tools:

| Area | Test tool | Where |
|------|-----------|-------|
| Core logic (TS) | Vitest | `packages/core/src/*.test.ts` |
| Rust (renderer, sinks, IPC) | `cargo test` | `#[cfg(test)]` modules / `tests/` |
| Native C++ camera DLLs | CTest + small harness | `native/vcam-windows/tests` |
| UI | Logic is pushed into core so it's covered there. Visual/manual checks for layout | — |

Commits: the failing test and the implementation may be committed separately (test first) so the history shows red → green.

## Consequences

- No logic goes into React components or Tauri commands without a test in core or Rust.
- CI fails if any test fails.
